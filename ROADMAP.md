# ROADMAP

This roadmap keeps the Zephyr vault professional, contributor-ready, and resilient as a long-lived personal knowledge system.

## Quick wins (1-2 weeks)
- Add `CONTRIBUTING.md` and normalize PR/commit expectations for documentation changes.
- Add consistency checks for frontmatter/date naming in `Daily/`, `Feelings/`, and `Growth/`.
- Add a maintenance checklist for broken wikilinks and orphan notes.
- Standardize `README` links to key navigation docs (`INDEX.md`, `CONTRIBUTING.md`, this roadmap).

## Medium (2-6 weeks)
- Introduce lightweight docs QA scripts (`lint:md`, link checks, structure checks).
- Add templates for project status notes and architecture decision notes.
- Define retention policy for `Archive/` and stale daily notes.
- Add `Projects/` index to make active work easier to discover.

## Big bets (1-3 months)
- Build automated vault health scoring (link density, stale notes, uncategorized files).
- Add semantic memory quality audits (coverage by domain, duplicate concept detection).
- Introduce periodic portfolio snapshots to track growth and system evolution over time.

## Strategic rewrites (quarter+)
- Migrate from ad hoc file conventions to schema-driven notes (validated metadata contracts).
- Build a unified operating model tying `Skills/`, `Systems/`, and `Projects/` to measurable outcomes.
- Introduce publish-safe views (public/private filtered exports) for professional sharing.
